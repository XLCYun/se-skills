# 检查项清单（31 项）

档位说明：

- **A** — 工具可直接计数。数字以静态工具输出为准，LLM 负责确认真伪（排除误报）、给解释与重构方向。工具缺失时降级为人工核对，confidence 上限"中"。
- **B** — LLM 判定，但判据操作化。逐单元核对：对每个适用单元给出 存在/不存在/不适用。
- **C** — 整体评级。不计数，对仓库整体给 0–5 锚定评分（Phase 4）。

severity 通用规则：判定标准中给出"中/高"阈值的按阈值；未明说时——实质损害可变更性或有正确性风险为**高**，明确存在但影响范围有限为**中**，真实但次要为**低**。

confidence 通用规则：多处直接证据或强结构性证据为**高**；局部证据清晰但覆盖有限为**中**；证据不完整的发现直接省略（不报 confidence 低的发现）。

## 结构（STR）

### STR-01 过长函数

- 档位：A（lizard）
- 定义：函数承担多个职责、控制流难以一句话概括。
- 判定标准：NLOC > 60 或圈复杂度 > 15 或嵌套深度 > 4 → 中；NLOC > 120 或圈复杂度 > 30 → 高。
- 边界：生成代码、框架强制的配置方法（如 Spring SecurityConfig）不计。
- 重构方向：抽取函数、分解条件逻辑、拆分循环、以多态取代条件分支。

### STR-02 过长参数列表

- 档位：A（lizard）
- 定义：函数接收超出调用方可轻松推理的信息量。
- 判定标准：参数 ≥ 5 → 中；参数 ≥ 8，或含 ≥ 2 个 boolean flag 参数切换行为 → 高。
- 边界：构造器注入的依赖参数（DI 框架）不计；builder 模式的链式 setter 不计。
- 重构方向：引入参数对象、直接传递整个对象、以查询取代参数、移除 flag 参数。

### STR-03 过大的类

- 档位：A/B（lizard 计规模，LLM 判职责）
- 别名：上帝对象（吸收自反模式清单）
- 定义：类拥有过多字段、方法或职责，成为不相关行为的聚集点。
- 判定标准：NLOC > 400 或方法数 > 25 或字段数 > 15 → 候选，由 LLM 确认职责数；职责 ≥ 3 个互不相关领域 → 中；同时是多个方向变更的汇聚点（上帝对象形态）→ 高。
- 边界：仅规模大但职责单一（如常量表、纯映射配置）不报；整体结构混乱归 CHG-03，本项只针对具体的类。
- 重构方向：抽取类、移动方法、提炼父类。

### STR-04 数据类

- 档位：B
- 定义：类基本只有字段加 getter/setter，本应与数据在一起的行为散落在别处。
- 判定标准：getter/setter/构造器占方法数 > 90%，且存在 ≥ 2 处外部代码对其字段做本应内聚的计算 → 中；该计算逻辑在外部重复出现 → 高。
- 边界：DTO/VO/传输对象、ORM 实体、record 类型在分层架构中合理存在，仅当行为散落条件同时成立才报。
- 重构方向：移动方法、封装记录、移除设值方法。

### STR-05 懒惰元素

- 档位：B
- 定义：可达但做得太少、不值得继续存在的类/函数/抽象（早期重构或过度设计留下的壳）。
- 判定标准：单元只有 ≤ 1 个有实义的成员，或仅转发一次调用且无隔离价值，且调用方 ≤ 2 处 → 中。
- 边界：**不可达**的代码归 DED-01 熔岩流；为未来需求预留的抽象归 OVR-01；纯转发但调用方众多的归 CPL-05 中间人。
- 重构方向：内联函数、内联类、折叠继承层次。

### STR-06 临时字段

- 档位：B
- 定义：字段只对某条狭窄调用路径有意义，大多数时间为 null 或无关。
- 判定标准：字段仅被单一方法（或单一调用链）读写，且其它路径下无意义 → 中；由此产生 null 检查扩散到 ≥ 3 处 → 高。
- 边界：延迟初始化的缓存字段、框架注入的可选依赖不计。
- 重构方向：抽取类、引入特例。

### STR-07 循环过重

- 档位：B
- 定义：命令式循环把本可更清晰表达的集合转换搞得难懂。
- 判定标准：循环体同时做过滤+转换+聚合中 ≥ 2 类操作，且嵌套 ≥ 2 层或使用 ≥ 2 个可变累积变量 → 中。
- 边界：有明确性能要求（热点路径、避免中间集合）的命令式循环不报；单纯"可以改成 stream"的样式偏好不报。
- 重构方向：用管道式处理取代循环。

## 重复（DUP）

### DUP-01 重复代码

- 档位：A（jscpd）
- 别名：复制粘贴式编程（吸收自反模式清单）
- 定义：多处共享几乎相同的控制流、分支或转换逻辑；修一个 bug 要在多处重复修改。
- 判定标准：jscpd 报告的 ≥ 15 行（或 ≥ 100 token）克隆对 → 中；同一克隆家族 ≥ 3 处，或克隆间已出现漂移（细微修改）→ 高。
- 边界：测试代码中的 setup 重复降一级报告；框架样板（如相似的 CRUD 端点骨架）由 LLM 确认是否可抽象后再报。
- 重构方向：抽取函数、上移方法、把共享行为抽成可复用模块。

### DUP-02 重复的条件分发

- 档位：B（Phase 3 跨文件项）
- 定义：围绕同一类型码/状态的 switch 或 if-else 链在多处重复出现，新增变体需要改多处。
- 判定标准：同一判别变量的分发逻辑出现 ≥ 2 处 → 中；≥ 3 处或分支集合已在各处不一致 → 高。
- 边界：单处的长 switch 不算本项（视复杂度归 STR-01）；由摘要中的"条件分发点"聚合判定。
- 重构方向：以多态取代条件分支、以子类取代类型码。

### DUP-03 接口不一致的平行类

- 档位：B（Phase 3 跨文件项）
- 定义：相似概念被实现成方法名/签名互不兼容的多个类，调用方本可共享同一接口。
- 判定标准：≥ 2 个类字段/方法语义高度重合但命名或签名不对齐，且调用方因此出现分叉处理 → 中；已引起重复代码或转换层扩散 → 高。
- 边界：分层约定的 DTO/VO/Entity 三件套不报，除非同层内出现平行；摘要歧义时下钻源码确认。
- 重构方向：修改函数声明、提炼父类、移动方法。

## 耦合（CPL）

### CPL-01 全局数据

- 档位：A/B（grep 计数候选，LLM 确认）
- 定义：状态可被许多位置全局访问并随意修改（公共静态可变字段、单例可变状态当共享临时空间）。
- 判定标准：public static 非 final 字段 / 模块级可变全局变量，被 ≥ 2 个模块写 → 中；承载业务状态且无同步保护 → 高。
- 边界：常量（static final 不可变）不计；框架管理的单例 Bean 本身不计，其内部可变共享字段计。
- 重构方向：封装变量。

### CPL-02 可变数据

- 档位：B
- 定义：状态暴露超出必要的写权限，多条带副作用的路径修改同一份数据，难以定位值在哪里被改。
- 判定标准：同一字段被 ≥ 3 个不同类写入 → 中；写路径分布在不同层（如 Controller 与定时任务都直接改实体状态）→ 高。
- 边界：与 CPL-01 的区分：本项针对对象/实体字段的写扩散，CPL-01 针对全局/静态作用域。
- 重构方向：封装变量、分离查询与修改、移除设值方法。

### CPL-03 依恋情结

- 档位：B（单元级在 Phase 2 判；跨模块聚合在 Phase 3 复核）
- 定义：函数与别的对象的数据交互多于自己所属对象，远距离施加逻辑。
- 判定标准：方法访问外部对象成员次数 ≥ 2 倍于本类成员，且该外部对象是数据主人 → 中；同一外部对象被多个方法依恋 → 高（行为整体放错位置）。
- 边界：纯编排层（Service 编排多个协作者）不报；判定对象是"读外部数据做计算"型方法。
- 重构方向：移动方法、抽取函数。

### CPL-04 消息链

- 档位：A/B（`\.\w+\(\)\.\w+\(\)\.\w+\(\)` 模式匹配候选，LLM 确认）
- 定义：`a.b().c().d()` 式长导航链，调用方知道了太多协作者内部结构。
- 判定标准：链长 ≥ 3 段且跨对象边界（非同对象流式 API）→ 中；同一条链在 ≥ 3 处重复出现 → 高。
- 边界：builder/stream/fluent API 的链式调用不计（同一对象返回自身或流水线）；Optional 链不计。
- 重构方向：隐藏委托关系、抽取函数。

### CPL-05 中间人

- 档位：B（Phase 3 跨文件项）
- 定义：类的主要工作是把调用转发给别处，几乎没有自己的行为，委托只增加仪式感。
- 判定标准：类中 ≥ 70% 方法为纯转发（单行委托、无参数加工、无策略选择）→ 中。
- 边界：有隔离价值的门面（跨模块边界、防腐层、对外 API 稳定层）不报——由 LLM 结合依赖方向判断；调用方极少的壳归 STR-05。
- 重构方向：移除中间人、内联函数。

### CPL-06 内幕交易

- 档位：C（Phase 4 整体评级）
- 定义：模块之间过于自由地交换私有细节，协作亲密度越过封装边界。
- 评分锚点：5 = 模块间仅通过公开接口协作；4 = 个别越界但有注释/约定管理；3 = 2–3 对模块互访内部字段或绕过接口；2 = 越界协作是常态，边界名存实亡；1 = 无法辨认封装边界；0 = 所有模块互相直接操作内部状态。
- 边界：单方向的行为放错位置归 CPL-03；本项针对双向/多向的私密交换。
- 纠正方向：移动方法、隐藏委托关系、以委托取代继承。

### CPL-07 被拒绝的遗赠

- 档位：B
- 定义：子类继承了不想要的行为或字段，继承关系破坏可替换性。
- 判定标准：子类覆写父类方法为空实现/抛 UnsupportedOperationException，或明显只使用继承面的一小部分 → 中；调用方必须先判类型再调用 → 高（LSP 已破坏）。
- 边界：适配器模式中有意的窄化不报。
- 重构方向：以委托取代子类、以委托取代父类。

## 命名与领域建模（NAM）

### NAM-01 神秘命名

- 档位：B
- 定义：命名无法传达意图：单字母、不透明缩写、拼音缩写、一词多义。
- 判定标准：公开 API（类名、公开方法、字段）中出现 → 中；同一标识符在不同上下文承载不同含义，或核心领域概念命名误导 → 高。
- 边界：循环变量 i/j/k、惯用缩写（ctx、cfg、req/resp）不计；只报影响理解领域逻辑的命名，不做风格纠察。
- 重构方向：重命名。

### NAM-02 基本类型偏执

- 档位：B（其中"魔法数字"子判据为 A 档，可静态计数）
- 别名：魔法数字（吸收自反模式清单）
- 定义：字符串/数字/布尔承载金钱、容量、状态、单位等领域概念，不变量只能靠约定维持。
- 判定标准：(a) 魔法数字子判据【A】：无名字面量承载领域含义（阈值、容量上限、状态码）出现 ≥ 3 处 → 中，同一字面量散落多文件 → 高；(b) 领域概念以裸 String/int 在 ≥ 3 个签名间传递且伴随重复校验/转换 → 中；状态机以魔法字符串比较驱动 → 高。
- 边界：0/1/-1、空串等惯用值不计；**该进配置文件的环境值**（端点、路径、密钥）归 CFG-01——区分口径：CFG-01 管"值不该写死在源码"，本项管"值该有领域类型"。
- 重构方向：以对象取代基本类型、用具名常量替换字面量、以子类取代类型码。

### NAM-03 数据泥团

- 档位：B（Phase 3 跨文件项）
- 定义：同样的 3–4 个字段/参数反复一起出现，代表一个缺失的领域对象。
- 判定标准：同一字段组合在 ≥ 3 个签名或类中共现 → 中；组合还伴随重复的成组校验逻辑 → 高。
- 边界：由摘要中的"参数组合"聚合判定；已有参数对象但未普及使用的，报为中并指出既有类型。
- 重构方向：抽取类、引入参数对象。

### NAM-04 注释掩盖混乱

- 档位：B
- 定义：长注释在为难懂的代码打补丁——解释"怎么工作"而不是"为什么存在"。
- 判定标准：≥ 10 行的实现步骤讲解型注释，或注释与代码已不一致 → 中；注释承认问题（"这里很乱""临时方案"）且代码确实难懂 → 高。
- 边界：API 文档注释（javadoc/docstring）、协议或算法的出处说明不计；注释少不构成本项。
- 重构方向：抽取函数、修改函数声明、引入断言。

## 变更边界（CHG，均为 C 档整体评级）

### CHG-01 发散式变化

- 定义：一个模块因很多彼此无关的原因而变化（领域规则、格式化、持久化、传输堆在一处）。
- 评分锚点：5 = 每个模块只有一类变更原因；4 = 个别模块混入次要关注点；3 = 1–2 个核心模块承载 ≥ 3 类无关变更原因；2 = 多数核心模块如此；1 = 关注点普遍无分离；0 = 任何需求变更都指向同一批文件。
- 证据要求：指出具体模块及其承载的变更原因清单。
- 纠正方向：拆分阶段、抽取类。

### CHG-02 霰弹式修改

- 定义：一类功能/策略变化需要在许多文件里做零碎修改，行为被稀薄分散在低内聚模块中。
- 评分锚点：5 = 典型变更可在 1–2 个文件内完成；4 = 个别变更类型需触碰 3–4 处；3 = 常见变更（如加一个字段/一种文件类型）需同步修改 ≥ 5 处且无单一收敛点；2 = 多类变更均如此；1 = 几乎所有变更都要横扫仓库；0 = 修改根本无法收敛。
- 证据要求：以 1–2 个假想变更（如"新增一种存储后端"）走查实际要触碰的文件数。
- 纠正方向：移动方法/字段、把分散计算集中为一次转换。

### CHG-03 结构混乱度

- 别名：意大利面代码（吸收自反模式清单；与 STR-01/CHG-01/CHG-02 计数项互斥，避免双重计分）
- 定义：整体结构缺乏模块化、关注点分离与职责归属，理解一个行为需要沿纠缠的控制流追踪。
- 评分锚点：5 = 分层清晰、依赖单向、职责可一句话概括；4 = 结构清晰但有少量跨层捷径；3 = 个别模块跨层调用（如 Controller 直接访问 Repository/写 SQL），部分业务逻辑无明确归属；2 = 分层名存实亡，控制流需跨 ≥ 4 个文件追踪一个简单行为；1 = 无可辨认结构；0 = 单文件巨石或完全纠缠。
- 证据要求：给出依赖方向违例清单与一条最难追踪路径的走查记录。
- 纠正方向：抽出清晰边界、恢复单向依赖、拆分职责。

## 过度设计（OVR，C 档整体评级）

### OVR-01 推测性泛化

- 别名：过早优化（作为性能特例子判据；原"偶发复杂度"已删除，其场景由本项与 CHG-03 覆盖）
- 定义：为尚未到来的需求提前引入抽象、钩子、扩展点或性能机制，复杂度没有当前需求支撑。
- 子判据（评分时综合）：(a) 未使用的扩展点/仅一个实现的接口层/空钩子；(b) **过早优化**：无测量依据的缓存、并发、池化、索引层，且无失效/回退策略；(c) 只为假设性未来服务的配置项与继承层次。
- 评分锚点：5 = 抽象都有 ≥ 2 个真实使用方或明确近期需求；4 = 个别一对一接口（惯例性，如 Service 接口）；3 = 2–3 处无使用方的抽象或 1 处无测量的性能机制；2 = 推测性抽象成风或多处无据性能机制；1 = 架构主体为假设需求服务；0 = 几乎全部复杂度无当前需求支撑。
- 边界：做得太少的壳归 STR-05；死代码归 DED-01；框架惯例样板不算推测（除非确实无人使用）。
- 纠正方向：折叠继承层次、内联、删除推测机制、优化前先补基准测试。

## 死代码（DED）

### DED-01 熔岩流

- 档位：A（覆盖/可达性工具 + grep 候选，LLM 确认可达性）
- 定义：不可达、陈旧或已废弃的代码仍留在仓库：无人引用的类/方法、被注释掉的大段代码、永假分支、废弃开关。
- 判定标准：确认不可达的单元（无引用、无反射/配置入口）→ 中；被注释掉的代码块 ≥ 30 行，或废弃路径与活跃路径纠缠（增加理解成本）→ 高。
- 边界：与 STR-05 的区分：本项 = 不可达/废弃；STR-05 = 可达但不值得存在。公开库的未使用导出 API 不计（可能有外部调用方）。
- 重构方向：删除死代码；用搜索、测试与运行时入口验证可达性后尽快删。

## 配置卫生（CFG）

### CFG-01 硬编码

- 档位：A（semgrep/gitleaks）
- 定义：该进配置的值直接写死在源码：凭据、密钥、端点、文件路径、端口、策略阈值、环境假设。
- 判定标准：环境类值（URL、路径、端口）写死 → 中；凭据/密钥/token 入库，或同一配置值散落 ≥ 3 个文件 → 高。
- 边界：与 NAM-02 的口径区分见彼处；测试代码中的固定测试值不计；示例配置文件中的占位符不计。
- 重构方向：迁移到配置文件/环境变量，集中管理共享常量。

## 工程判断（ENG，C 档整体评级）

### ENG-01 重复造轮子

- 定义：已有稳定方案足够适用时仍自研，抬高时间成本、维护成本或正确性风险。
- 评分锚点：5 = 恰当复用成熟方案，自研处有明确理由；4 = 个别不必要自研但质量尚可；3 = 1–2 处安全/基础设施级自研（如手写 JWT 解析、手搓连接池）且质量存疑；2 = 多处此类自研；1 = 系统性拒绝成熟方案；0 = 关键路径全部脆弱自研。
- 判定纪律：先在 README/文档中寻找自研理由（教学要求、约束条件），有正当理由的降档或不计；对安全敏感组件（鉴权、加密、会话）的自研从严。
- 纠正方向：有选择地替换脆弱自研，不采用现有方案时记录原因。

## 测试质量（TST，由测试分片代理执行）

### TST-01 错位测试

- 档位：B
- 定义：测试类型与被验证行为不匹配：用慢的端到端测试覆盖本应单元测试的逻辑，或反之。
- 判定标准：纯函数逻辑仅被 E2E/集成测试覆盖 ≥ 3 处 → 中；测试金字塔倒置（集成/E2E 数量 > 单元测试且单元可测逻辑大量存在）→ 高。
- 边界：以仓库实际分层为准，不苛求教科书比例；无测试的情况在覆盖率指标中体现，不在本项报。
- 纠正方向：把测试重新平衡到合适层级，删除增加成本不增信心的冗余测试。

### TST-02 测试内部实现

- 档位：B
- 定义：测试耦合到私有方法、内部状态、调用顺序或偶然结构；mock/spy 替代了行为验证。
- 判定标准：测试通过反射访问私有成员，或 verify 调用次数/顺序而无行为断言 → 中；此类测试占测试数 ≥ 30%，或存在"只有 mock 交互、无任何可观察行为断言"的测试 → 高。
- 边界：对边界接口（外部服务、时钟）的 mock 是正当的；判定对象是对**自己模块内部**的过度 mock。
- 纠正方向：断言可观察行为与外部契约，让测试替身聚焦真正边界。

### TST-03 只测 Happy Path

- 档位：B
- 定义：测试只覆盖预期场景，跳过失败、边界与非法输入；错误处理路径基本无测试。
- 判定标准：对含错误分支的公开 API，负向/边界测试占比 < 10% → 中；安全或数据完整性相关路径（鉴权失败、配额超限、并发冲突）完全无负向测试 → 高。
- 边界：以 API 面为分母（哪些公开行为有错误分支），不是简单数测试个数；无任何测试的仓库本项记"不适用"，在测试覆盖指标中体现。
- 纠正方向：补边界场景与失败路径，复查高风险流程缺失的负向测试。

## 分诊指引

发现很多时，优先报告：扭曲变更边界的、迫使改动扩散的、遮蔽领域逻辑的、把行为从数据身边拆散的、通过可变共享状态制造正确性风险的。

关联模式（帮助归类，不做重复计分）：

- STR-03 过大的类 ↔ CHG-01 发散式变化常同时出现：具体类报 STR-03，仓库整体倾向进 CHG-01 评分
- NAM-03 数据泥团 ↔ NAM-02 基本类型偏执常暗示同一个缺失的领域对象：字段成组共现报 NAM-03，单值缺类型报 NAM-02
- CPL-03 依恋情结 ↔ CPL-04 消息链都暴露行为放错位置：按"计算放错地方"vs"导航链过长"归类
- 同一现象只计一次：按上述边界字段归入最特异的一项
