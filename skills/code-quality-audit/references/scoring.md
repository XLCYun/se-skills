# 评分公式与默认权重

目标：把发现与评级折算成 0–100 的维度分和一个加权总分（越高越好），使不同规模的仓库可横向比较。全部公式由 `aggregate.py` 执行，人不手算。

## 1. 加权发现密度（A/B 档计数项）

对每个维度 d：

```
D(d) = Σ over findings in d [ w(severity) ] / KLOC
w(high)=5, w(medium)=2, w(low)=1
```

- KLOC 分母：TST 维度用测试代码 KLOC（为 0 时用源码 KLOC 并在报告注明）；其余维度用非测试源码 KLOC
- 去重后计数：同一 `(item_id, file, unit)` 只计一次（aggregate.py 强制）

## 2. 密度 → 分数映射

```
S_density(d) = 100 × max(0, 1 − D(d) / DMAX(d))
```

`DMAX` = "密度达到多少记 0 分"的封顶值。默认统一 8.0（加权发现/KLOC），可按维度在权重文件中覆盖。选择线性映射而非指数是为了让分差可解释（每 1 密度 ≈ 12.5 分）。

## 3. C 档评级 → 分数

```
S_rating(item) = score × 20        # 0–5 → 0–100
```

## 4. 维度分

- 纯计数维度（结构、重复、命名与领域建模、死代码、配置卫生、测试质量）：`S(d) = S_density(d)`
- 纯评级维度（变更边界、过度设计、工程判断）：`S(d) = mean(该维度各 item 的 S_rating)`
- 混合维度（耦合 = 6 个计数项 + CPL-06 评级项）：`S(d) = mean(S_density(d), S_rating(CPL-06))`——计数部分整体算一个分量，每个评级项各算一个分量，取平均

## 5. 加权总分

```
Total = Σ S(d) × weight(d) / 100
```

默认权重（合计 100）：

| 维度 | 权重 | 理由 |
|---|---|---|
| 结构 | 18 | 可维护性主干 |
| 耦合 | 14 | 可维护性主干 |
| 测试质量 | 15 | 交付信心主干 |
| 重复 | 10 | |
| 命名与领域建模 | 10 | |
| 变更边界 | 10 | 整体演进能力 |
| 配置卫生 | 10 | 含安全（凭据入库） |
| 过度设计 | 5 | |
| 死代码 | 4 | 影响小 |
| 工程判断 | 4 | 影响小 |

覆盖方式：`aggregate.py --weights my-weights.json`，文件形如 `{"weights": {"结构": 20}, "dmax": {"结构": 6.0}}`，未提到的用默认值。

## 6. 有效性护栏

- **覆盖审计不通过（有缺口单元）时不出分**，aggregate.py 退出码 2 并列出缺口，重派后重跑
- 工具缺失导致 A 档降级人工核对的维度，报告中该维度分数旁标注 `*`（可复现性弱于其它维度）
- 多项目对比时，所有项目必须使用同一版 checklist、同一权重文件，report.json 中记录两者的哈希以供核对
